هذا التغيير يضيف صفحات إدارة منفصلة إلى واجهة POFRI:

- إدارة المستخدمين (للمدير الأعلى فقط): دعوة بالبريد، تحديد الدور (admin أو data_entry)، تعديل الدور، تعطيل الحساب وإعادة تفعيله. لا يوجد حذف نهائي لحسابات Auth حتى لا تتأثر سجلات MORS المؤرشفة.
- ملفات العاملين: إضافة وتعديل ملف مستقل، بحث بالاسم/الرقم الوظيفي، واستيراد CSV أو Excel. الأعمدة المطلوبة: employee_name, registration_number, date_of_birth. الأعمدة الاختيارية: sector, job_title, site, notes.
- ربط التقييم بملف عامل: اختيار عامل مسجل يملأ الاسم والرقم الوظيفي وتاريخ الميلاد والوظيفة والموقع في نموذج التقييم.
- تاريخ الميلاد والعمر: يحسب العمر بالسنوات المكتملة في تاريخ التقييم، ويحفظ تاريخ الميلاد والعمر داخل JSONB في سجل التقييم.
- حذف التقييم: زر حذف نهائي للمدير الأعلى فقط، مع سياسة RLS مستقلة.

## خطوات تفعيل قاعدة البيانات

بعد مراجعة ودمج التغيير، شغّل محتوى supabase/pofri-workers-and-admin.sql مرة واحدة في SQL Editor لمشروع Supabase vvagucmjmjoxnyumxtcq.

ينشئ ذلك جدول pofri_workers وسياسات RLS، ويضيف سياسة حذف تقييمات POFRI للمدير الأعلى فقط. لا يعدّل جداول MORS أو حساباته أو سجلاته.

## تفعيل وظيفة إدارة المستخدمين

انشر Edge Function من الملف supabase/functions/pofri-user-management/index.ts باسم pofri-user-management مع تفعيل JWT verification. تستخدم الوظيفة مفاتيح Supabase السرية من متغيرات البيئة؛ لا تضع أي مفتاح سري في GitHub أو JavaScript المتصفح.

تتحقق الوظيفة من هوية المدير الأعلى الثابتة ومن دوره الحالي في app_users قبل تنفيذ أي عملية. لا يمكنها تعديل أو تعطيل أو حذف حساب المدير الأعلى. الحذف النهائي لحساب مستخدم يزيل حساب Auth وملف app_users المرتبط به، لكنه لا يحذف سجلات التقييم القديمة.
